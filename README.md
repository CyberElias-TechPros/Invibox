# Invibox

what are all the features it should have and other innovations: i want to make a wedding/event invitation webapp for all kinds of events possible

Absolutely. If you want this to be more than a simple “pick a template → edit text → share a link” invitation maker, I’d design it as a full Event Invitation + Event Experience Platform.

The big idea:

Create the invitation once, and let it become the entire digital experience surrounding the event.

That means weddings, birthdays, funerals, graduations, baby showers, naming ceremonies, church events, corporate events, conferences, parties, anniversaries, traditional ceremonies, reunions, launches, dinners, etc.

1. The Core Product

Think of the app as having 5 interconnected layers:

Invitation Studio — create the visual invitation
Event Website — the invitation becomes a mini-site
Guest Management — RSVP, guest lists, households, seating
Event Operations — reminders, schedules, vendors, check-in
Event Memory — photos, videos, guest messages, memories

This gives you a much larger product than Canva-style invitation design.

import { Router } from 'itty-router';

export interface Env {
  DB: D1Database;
  R2_STORAGE: R2Bucket;
  JWT_SECRET: string;

const router = Router();

// Middleware: Verify Access Token for Guests
const authenticateGuest = async (request: Request, env: Env) => {
  const url = new URL(request.url);
  const token = url.searchParams.get('token') || request.headers.get('Authorization')?.replace('Bearer ', '');
  
  if (!token) {
    return new Response(JSON.stringify({ error: 'Missing access token' }), { status: 401 });
  }

  const guest = await env.DB.prepare(
    'SELECT * FROM guests WHERE access_token = ?'
  ).bind(token).first();

  if (!guest) {
    return new Response(JSON.stringify({ error: 'Invalid access token' }), { status: 403 });
  }

  (request as any).guest = guest;
};

// GET: Fetch Microsite & Event Details for Guest
router.get('/api/v1/microsite/:slug', async (request: Request, env: Env) => {
  const { slug } = request.params;
  const url = new URL(request.url);
  const token = url.searchParams.get('token');

  // Fetch Core Event
  const event = await env.DB.prepare(
    'SELECT * FROM events WHERE slug = ?'
  ).bind(slug).first();

  if (!event) {
    return new Response(JSON.stringify({ error: 'Event not found' }), { status: 404 });
  }

  let guestData = null;
  let allowedSubEvents = [];

  if (token) {
    guestData = await env.DB.prepare(
      'SELECT id, first_name, last_name, plus_one_allowed, dietary_restrictions FROM guests WHERE access_token = ? AND event_id = ?'
    ).bind(token, event.id).first();

    if (guestData) {
      // Fetch sub-events explicitly assigned to this guest
      const subEventsResult = await env.DB.prepare(`
        SELECT se.*, sei.rsvp_status, sei.meal_preference 
        FROM sub_events se
        JOIN sub_event_invitations sei ON se.id = sei.sub_event_id
        WHERE sei.guest_id = ?
      `).bind(guestData.id).all();
      
      allowedSubEvents = subEventsResult.results;
    }
  }

  // Fallback to public sub-events if no token provided
  if (!guestData) {
    const publicSubEvents = await env.DB.prepare(
      'SELECT * FROM sub_events WHERE event_id = ? AND is_private = 0'
    ).bind(event.id).all();
    allowedSubEvents = publicSubEvents.results;
  }

  return new Response(JSON.stringify({
    event,
    guest: guestData,
    subEvents: allowedSubEvents
  }), {
    headers: { 'Content-Type': 'application/json' }
  });
});

// POST: Submit Multi-Event RSVP
router.post('/api/v1/rsvp', async (request: Request, env: Env) => {
  const body = await request.json();
  const { token, dietaryRestrictions, plusOneName, rsvpResponses } = body;

  const guest = await env.DB.prepare(
    'SELECT id, event_id FROM guests WHERE access_token = ?'
  ).bind(token).first();

  if (!guest) {
    return new Response(JSON.stringify({ error: 'Unauthorized token' }), { status: 401 });
  }

  // Update guest details
  await env.DB.prepare(
    'UPDATE guests SET dietary_restrictions = ?, plus_one_name = ? WHERE id = ?'
  ).bind(dietaryRestrictions || null, plusOneName || null, guest.id).run();

  // Process sub-event responses in batch
  if (Array.isArray(rsvpResponses)) {
    for (const response of rsvpResponses) {
      const { subEventId, rsvpStatus, mealPreference } = response;
      await env.DB.prepare(`
        UPDATE sub_event_invitations 
        SET rsvp_status = ?, meal_preference = ?, updated_at = CURRENT_TIMESTAMP
        WHERE sub_event_id = ? AND guest_id = ?
      `).bind(rsvpStatus, mealPreference || null, subEventId, guest.id).run();
    }
  }

  return new Response(JSON.stringify({ success: true, message: 'RSVP submitted successfully' }), {
    headers: { 'Content-Type': 'application/json' }
  });
});

  fetch: router.handle

Where you can actually innovate

Multi-event series as a first-class concept. A Nigerian wedding might be an introduction, a traditional ceremony, a white wedding, and a reception — different dates, different venues, overlapping but distinct guest lists. Most apps make you create four separate events. Treat the series as the object and per-event invitations as children of it. This alone could be your wedge.

AI as a wedding-planning copilot, not a gimmick. Generate wording in the right register for the culture and formality level. Draft the schedule. Suggest seating arrangements from relationship data. Answer guest questions automatically from your event info ("Is there parking?"). Write thank-you notes personalized to each gift.

WhatsApp-native everything. In much of the world the invitation is a WhatsApp forward. Let guests RSVP by replying to a WhatsApp message without opening a browser. Let hosts manage the guest list from a WhatsApp bot. Nobody does this well.

Offline-first guest experience. The invite page works with no signal — cached venue map, schedule, and check-in QR. Venues have terrible reception.

Cultural template packs built with actual designers from each tradition, not generic templates with a motif slapped on.

Vendor marketplace and coordination. Photographers, caterers, DJs get scoped access to the run-of-show and guest count. Long-term this is where the revenue is — you're sitting on high-intent demand.

Privacy controls that are actually thought through. Unlisted links, per-guest access tokens, hide the guest list from guests, auto-delete photos after N months, and a clear stance on who owns the data. Weddings involve family drama; give hosts real control.

Accessibility as a feature, not compliance theater. Screen-reader-clean invites, captions on video invites, high-contrast mode, large-print export for older relatives.

Freemium with paid tiers on guest count and features; per-event one-time fee (people hate subscriptions for a one-day thing); take a cut of cash gifts and ticket sales; premium designer templates; vendor marketplace commission; physical print fulfillment.
